# Vercel 공개 미리보기 배포

Vercel 프로젝트의 Root Directory는 `on-client`로 지정합니다. 새 `vercel.json`은 `src/server.mjs` 자동 진입점 대신 `api/index.mjs`를 명시적으로 빌드하고 모든 요청을 전달합니다. 제공 서버와 학생 구현은 변경하지 않습니다.

## 배포 순서

1. `api/index.mjs`, `vercel.json`, 이 안내와 13단계 학생 변경이 저장소에 포함됐는지 확인합니다. 공식 과제 커밋 도구는 새 `api`·설정·최상위 문서를 자동 포함하지 않을 수 있습니다. 프로젝트 최상위의 `커밋_전_확인_및_실행_안내.md`를 먼저 따릅니다.
2. Vercel에서 Root Directory를 `on-client`, Framework Preset을 Other로 확인합니다. 빌드·출력 명령의 기존 수동 Override는 해제하고 저장된 설정을 사용합니다. `builds`가 빌드를 명시하므로 관련 대시보드 설정이 적용되지 않는다는 경고가 나올 수 있습니다.
3. Node.js는 24.x를 선택합니다. 기존 package.json의 24.19.0 지정은 제공 파일 보존을 위해 변경하지 않았습니다. 플랫폼의 실제 패치 버전에 따라 기존 엔진 경고는 남을 수 있습니다.
4. 위 파일이 포함된 버전으로 재배포합니다. 실제 배포는 이 문서를 작성하면서 수행하지 않았습니다.
5. 배포 주소에서 화면·세 메뉴·학생 표시·다시 불러오기를 확인합니다. `/student/extension.mjs`는 JavaScript로 응답해야 합니다.

## 동작 범위

- 공개 화면과 조회 API만 제공하는 미리보기입니다. 회사 시스템·학원 계정·개인 PC의 실제 로그인 정보에 연결하지 않습니다.
- 기본 제공 서버를 외부 어댑터 없이 실행하므로 실제 신원 API의 503과 ‘연결 없음’ 표시는 예상된 결과입니다. 예제나 실제 연결 성공으로 바꾸지 않습니다.
- 제공 서버의 로컬 주소 검사는 유지하고 별도 진입점에서 허용한 GET 경로만 내부 서버에 전달합니다. 서버는 외부 인터페이스가 아닌 loopback에 임시 포트를 엽니다.
- AI 호출·로그인 연결·접근 판정·보안 조치 등의 POST 요청은 405로 차단합니다. 취약점 스캔 등 허용하지 않은 경로는 404입니다.
- 키·개인 설정을 Vercel 환경 변수나 배포 파일에 추가할 필요가 없습니다. 이 진입점은 AI 환경 설정을 사용하지 않습니다.
- 이 배포는 로컬 앱 실행 확인이나 ALEPH 공식 제출·판정을 대신하지 않습니다.

## 확인 범위

로컬 HTTP 연결 검증과 Vercel 실배포 결과를 구분해야 합니다. 실제 Vercel 배포 후의 동작은 재배포 결과에서 확인합니다. 로컬 Node.js 지원 버전과 플랫폼 빌드 차이 때문에 로컬 테스트만으로 실배포 성공을 보장하지 않습니다.

### 이번 로컬 검증 결과

- Node.js 24.19.0에서 새 default handler를 실제 HTTP 서버에 연결해 검증했습니다.
- HTML, JavaScript, CSS, 학생 모듈, 대표 이미지의 200 응답을 확인했습니다.
- me·apps·events·devices·sessions API는 disconnected 모드의 503, diagnostics는 200을 확인했습니다.
- cross-site API 조회 403, POST 405, 비공개 경로·지원하지 않는 주소 404, 쿼리 포함 요청 400을 확인했습니다.
- 동시 10개 화면 요청이 모두 200으로 응답했습니다.
- Vercel 클라우드 빌드·실배포·실제 브라우저 화면 검증은 별도이며 아직 수행하지 않았습니다.
