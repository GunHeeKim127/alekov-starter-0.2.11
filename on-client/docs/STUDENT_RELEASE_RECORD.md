## 3. 다른 위치에서 따라 하는 절차

실행 위치·지원 환경·정상 신호는 [STUDENT_RUNBOOK.md](STUDENT_RUNBOOK.md)를 따릅니다. 그 문서의 기존 PC 경로는 사례이며 다른 PC에서 그대로 사용할 필수 경로가 아닙니다. 아래 변수에는 자신의 실제 경로·실제 제출 커밋을 지정합니다. 기존 폴더와 같은 경로를 대상에 넣지 않습니다.

원본 Git 최상위 PowerShell에서 먼저 읽기만 합니다.

```powershell
git status --short
git remote get-url origin
git branch --show-current
git rev-parse HEAD
```

원본이 보존된 상태에서 프로젝트 밖의 새 폴더로 복제합니다. 원격에 최종 커밋을 올리지 않은 이번 작업은 원본 로컬 폴더를 원천으로 사용했습니다. 원격을 사용하려면 그 원격에서 최종 커밋을 실제 받을 수 있는지 먼저 확인합니다. 공개로 바꿀 필요는 없습니다.

```powershell
$releaseSource = Read-Host '원본 로컬 저장소 절대 경로 또는 커밋이 존재하는 저장소 URL'
$releaseCopy = Read-Host '아직 존재하지 않는 복제 폴더의 절대 경로'
$releaseCommit = Read-Host '제출할 실제 40자리 커밋 번호'
if (Test-Path -LiteralPath $releaseCopy) { throw '기존 폴더를 보존합니다. 새 경로를 지정하세요.' }
git clone --no-hardlinks --no-checkout -- $releaseSource $releaseCopy
if ($LASTEXITCODE -ne 0) { throw '복제 실패. 기존 작업은 유지하세요.' }
git -C $releaseCopy checkout --detach $releaseCommit
if ($LASTEXITCODE -ne 0) { throw '커밋을 확인하지 못했습니다. 실행하지 마세요.' }
git -C $releaseCopy rev-parse HEAD
```

로컬 clone의 origin은 원본 로컬 경로가 됩니다. 복제본의 origin을 제출 URL이라고 오인하지 않습니다. 제출 저장소 주소는 1장의 원본 GitHub URL이며 원본 origin은 바꾸지 않습니다.

복제 폴더의 `on-client`에서 새 PowerShell을 열고, 지원 Node.js를 확인합니다. 경로를 옮겨도 코드·설정 견본은 상대 경로를 사용합니다. 런타임이 없는 PC에는 지원 버전을 준비해야 하며, 이 기록의 로컬 캐시 경로가 모든 PC에 존재한다고 가정하지 않습니다.

```powershell
Set-Location -LiteralPath (Join-Path $releaseCopy 'on-client')
node --version
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Port 5198
```

브라우저 `http://127.0.0.1:5198/`에서 제목·세 메뉴·미연결 표시를 확인합니다. 일반 실행은 Ctrl+C로 종료한 뒤 같은 명령으로 재실행합니다. 실제 자동 검사에서는 같은 도구에 `-Background`를 추가하고, 이번 복제 경로의 서버인 것이 확인된 프로세스만 종료했습니다. 다른 node나 원본 서버는 종료하지 않습니다. 포트가 사용 중이면 다른 번호를 선택하고 URL도 바꿉니다. 실행 도구는 설치나 전역 PATH 변경을 하지 않습니다.

확인된 설치 단계는 별도 npm 설치 없이 실행하는 것입니다. 실 OSV 대조용 package-lock.json을 만들거나 의존성을 낮춰 취약점을 만드는 작업은 하지 않습니다. 실제 연결이 필요한 설정은 담당자에게 새 환경에 맞게 안내받으며, `.env.example`은 비밀 없는 견본일 뿐 연결 완료 설정이 아닙니다.

| 실제 조치 SQLite 기록 | 운영자가 지정한 기존 DB와 저장 정책으로 관리. 학생이 DB를 만들거나 경로를 임의 지정하지 않음 | 운영자의 일관된 SQLite 백업·복원 절차와 대상·requestId·receiptId·version·효과를 확인 | 실행 중 DB 파일만 임의 복사하지 않음. 이 프로젝트에서 실제 DB 백업·복원은 미확인 |
| SDP 접속 기록·XDR·원천 효과 | 원천 시스템 보존 정책 사용 | 담당자 권한으로 본인 범위 재조회 | 코드 clone이 서버 기록·이전 조치 효과를 백업하지 않음 |

별도 코드 백업이 필요할 때의 예시입니다. 새 경로만 선택하고 기존 백업을 덮어쓰지 않습니다.

```powershell
$releaseBackup = Read-Host '프로젝트 밖의 아직 없는 Git bundle 절대 파일 경로'
if (Test-Path -LiteralPath $releaseBackup) { throw '기존 백업을 보존합니다.' }
git bundle create $releaseBackup --all
git bundle verify $releaseBackup
```

복원은 원본에 덮어쓰지 않고 새 폴더에서 `git clone`으로 수행합니다. 위 bundle 명령은 계획 예시이며 이번에 실제 생성·복구했다고 주장하지 않습니다. 로컬 clone 재현은 실제 수행했습니다. 무시된 개인 파일과 실행 중 DB를 이 코드 백업으로 보호했다고 가정하지 않습니다.

## 7. 문제·변경 기록과 지원 범위

| 항목 | 원인·처리 | 상태 |
|---|---|---|
| 첫 로컬 clone 시 Git 보조 프로세스 제한 | 샌드박스의 Windows Git 보조 프로세스 권한 제한. 새 경로에서 승인된 로컬 복제로 재시도 | 복제 완료. 앱 코드를 고친 문제가 아님 |
| 기본 Node v20.9.0 | 제공 도구 지원 범위 밖 | 별도 v24.22.1 선택. 시스템 기본·전역 PATH는 미변경 |
| 최종 커밋과 문서 해시의 자기 참조 | 문서 본문에 자기 커밋 해시를 박으면 커밋이 다시 바뀜 | 최종 HEAD·JSON commit·별도 검증 결과를 일치시켜 기록 |
| 실제 AI·SDP·조치·OSV | 정식 설정·권한·실행 결과 없음 | UNV/미확인. 전체 운영 목표에서 제외하지 않음 |

지원 환경은 학생 실행 설명서의 Windows·Node 허용 범위에 한정합니다. 이번에 직접 실행한 런타임은 v24.22.1 하나입니다. 다른 OS·다른 Node 전체 버전·새 PC·실제 권한 연결·19단계 실집행·실제 OSV 및 공식 수료 판정은 인증하지 않습니다. 22단계 통과가 나오더라도 원문 검토 기준 수료이며 운영 인증이나 v1.0 자동 인증이 아닙니다.

## 8. 제출할 때

최종 문서와 누적 코드가 담긴 실제 커밋을 확인합니다. 21·22단계는 현재 공식 안내에 따라 과제 화면에 원본 GitHub 저장소 주소와 실제 40자리 커밋을 직접 입력합니다. 비공개를 공개로 바꿀 필요는 없습니다. 워크벤치 제출 준비 지원 범위를 임의로 넓히지 않습니다.

프로젝트 밖 기존 원문 도구의 경로와 출력 부모 폴더를 확인한 뒤, **원본 Git 최상위**에서 실행합니다. clone origin은 로컬 경로이므로 원문 JSON 생성은 원본 GitHub origin이 있는 원본 폴더에서 합니다.

```powershell
$releaseCommit = Read-Host '최종 검증 결과와 일치하는 실제 40자리 커밋 번호'
$sourceTool = Read-Host 'student-source-cli.mjs의 실제 절대 경로'
$sourceOutput = Read-Host '프로젝트 밖의 아직 없는 JSON 절대 파일 경로'
node $sourceTool --commit $releaseCommit --output $sourceOutput
```

지원 Node.js를 선택하고 실행합니다. 이 도구는 커밋된 원문만 묶고 앱 실행·업로드·제출을 하지 않습니다. 원문 JSON에 포함된 문서·코드와 커밋의 일치 여부를 검증합니다. 같은 단계의 비공개 원문 선택란에서 JSON을 선택하고 저장소·커밋·단계를 확인한 뒤 직접 제출합니다. 원문 전달만 실패하면 기존 접수를 유지하며 「원문만 다시 보내기」를 사용합니다. 이 기록 작성 시 push·포털 제출·공식 판정을 실행하지 않았습니다.
